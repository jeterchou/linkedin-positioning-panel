運用人工智慧協助審查 LinkedIn 個人檔案的 Skill，著重專業定位、有依據的文字修訂，以及個人、團隊與合作成果的清楚歸屬。適用於不同產業與職涯階段。

這是一套以指令運作的 Skill，並非獨立應用程式、LinkedIn 整合服務或真人招募團隊，不預測錄取結果或 LinkedIn 搜尋排名。

## 功能

- **General Audit｜整體審查**：無須指定目標職缺，評估專業身份、資歷訊號、可信的差異化及表達清晰度。
- **Target Role Audit｜目標職務審查**：依提供的職缺描述評估，區分「缺乏證據」與「實際不符合」。
- **七個審查視角**：高階人才招募者、用人主管、企業主管、領域同儕、國際／跨市場讀者、跨部門合作夥伴及第一印象讀者。
- 建立來源清單、欄位涵蓋表、證據台帳、名稱關係與衝突檢查、改善優先順序、保留事實的修改稿及前後複評。
- 區分無法取得的證據與錯誤主張，並在使用者補充證據後更新判斷。
- **只有在你明確授權時**，才另外使用獨立的事實檢查代理，最多修正一輪並複查一次。這是對照草稿與提供的來源，不等於外部查證。

## 輸入資料與來源範圍

建議先提供 LinkedIn 匯出的 Profile PDF，或直接貼上個人檔案文字。匯出檔未涵蓋的區段可用截圖補充。公開 LinkedIn 網址僅作輔助來源，成功開啟網址不代表已取得完整內容；只提供網址，不足以開始審查。匯出資料缺少的區段會標示為**未提供**，不推定 LinkedIn 頁面沒有該區段。

Skill 只開啟你指定、附加或貼上的來源；經授權的事實檢查代理也受同樣的範圍限制。同一資料夾中的其他檔案最多只列出檔名，不會開啟。沒有提供個人檔案、指定的路徑不存在，或只提供網址時，Skill 會先提出一個問題，不會自行猜測或改用其他檔案。

不需要，也不會要求密碼、登入 Cookie 或工作階段權杖。Skill 不繞過存取限制，也不會直接發布修改到 LinkedIn。

## 執行方式

| 項目 | 預設 | 何時改變 |
| --- | --- | --- |
| 七個審查視角 | 在同一脈絡中**模擬**，揭露文字為「Seven simulated perspectives; not seven independent agents or real hiring professionals.」 | 只有你在該次執行中明確要求以個別代理擔任審查者時才改變，揭露文字改為「Seven separate reviewer agents; not real hiring professionals.」 |
| 事實檢查 | 由作者執行並標明為**自我檢查**，不算獨立驗證 | 只有你明確授權事實檢查代理時才改變；該代理只讀取你指定的來源與草稿 |

環境中有代理工具，不代表已獲授權。授權事實檢查代理，也不代表授權七個審查代理。Skill 不宣稱任何代理使用了哪個模型；只有主機實際回報時才記錄模型資訊。

## 不安裝 Skill 的快速測試方式

在能讀取 Markdown 與輸入檔案的 AI 環境，提供 `SKILL.md` 及個人檔案，輸入：

> 請讀取 SKILL.md，依照指令對提供的 LinkedIn 個人檔案執行 General Audit。只使用提供的資料快照，不使用過往記憶中的個人資料，也不瀏覽網路。將三份報告存到〔公開專案之外的私人資料夾〕。請以繁體中文撰寫分析，LinkedIn 修改稿維持英文。我授權在環境支援時使用一個獨立事實檢查代理，依 Skill 完成限定次數的修正與複查，並揭露實際執行方式與替代方式。

不需要代理時，刪除授權那一句即可，Skill 會改以標明的自我檢查進行。這種方式測試的是指令流程，不等於驗證原生 Skill 偵測或安裝功能。

## 提供測試者的 Claude Code 安裝方式

將專案 `skills/` 目錄中的 `linkedin-positioning-panel` 資料夾（含其中的 `LICENSE`）複製到以下其中一個位置：

| 使用範圍 | SKILL.md 的目的路徑 |
| --- | --- |
| 目前專案 | `.claude/skills/linkedin-positioning-panel/SKILL.md` |
| 個人安裝 | `~/.claude/skills/linkedin-positioning-panel/SKILL.md` |

僅下載本專案的 `skills/` 資料夾，不代表已完成 Claude Code 專案安裝。複製後，在相關專案開啟 Claude Code 工作階段，例如輸入：

```text
/linkedin-positioning-panel inputs/Profile.pdf
```

這樣的簡短指令會以模擬方式執行七個視角、進行標明的自我檢查，並產出三份報告檔案（見下方「輸出」）。如果要使用事實檢查代理或指定輸出位置，請直接寫明：

```text
/linkedin-positioning-panel 請對 inputs/Profile.pdf 執行 General Audit。只使用提供的來源。報告存到 ~/private/linkedin-review/。我授權使用一個獨立事實檢查代理。分析使用繁體中文，LinkedIn 修改稿維持英文。
```

執行 Target Role Audit 時，另提供目標職缺描述。使用者須具備目前有效的 Claude Code 存取方式，以及能執行相關操作的模型；模型與服務費用不包含在本專案授權內。最新載入方式請參閱 [Claude Code 官方 Skill 文件](https://code.claude.com/docs/en/skills)。

## 以 Plugin 方式載入

專案根目錄同時也是一個 Claude plugin：設定檔是 `.claude-plugin/plugin.json`，Skill 放在 `skills/`。本專案尚未在 Anthropic 的 plugin 目錄上架；上架前，請使用上方的複製安裝方式，或依本節方式載入。

### Claude Code

clone 本專案後，**在專案資料夾內**啟動 Claude Code，下方範例中的 `examples/` 路徑才會正確：

```text
git clone https://github.com/jeterchou/linkedin-positioning-panel
cd linkedin-positioning-panel
claude --plugin-dir .
```

以 plugin 方式載入時，Skill 的完整名稱是 `linkedin-positioning-panel:linkedin-positioning-panel`。在 Claude Code 2.1.322 的確認中，簡短指令 `/linkedin-positioning-panel` 也能載入。若另外安裝了同名 Skill，請使用完整名稱。

專案資料夾本身是 git 儲存庫。若沒有指定輸出位置，Skill 不會把報告寫進這個資料夾；請見「輸出」一節。

### claude.ai 對話與 Cowork

Plugin 中的 Skill 也會在 claude.ai 對話與 Cowork 中載入。上架前，請用 plugin 資料夾的壓縮檔加入帳號：**Customize → Plugins → Add → Upload plugin**。Skill 在那裡的程式碼沙箱中執行，因此必須在 Settings → Capabilities 開啟 **Code execution and file creation**。

在一次上傳測試中，Skill 在審查報告中自行回報的 SKILL.md SHA-256（`92cfa6c5c99898fc4548a1e5ee67be3cada176aa71479357cc1ee97f04af4cf3`），等於把儲存庫檔案開頭設定區中多行的 `description` 改成單行後的結果，其餘內容完全相同。這只是單次觀察，不能確定是平台的固定行為。同一次測試中，plugin 頁面顯示的名稱是「Linkedin positioning panel」，沒有使用 `displayName`，圖示也是通用圖示。

claude.ai 對話已測試一次（見「測試狀態」）。Cowork **尚未測試**。

## 範例提示

範例使用 `examples/` 中的虛構個人檔案。實際使用時，請換成你自己的 Profile PDF 或貼上的文字。

### 在 Claude Code 中（從專案資料夾啟動）

1. 整體審查，採預設交付方式：
   `/linkedin-positioning-panel 請對 examples/sample-profile-zh.md 執行 General Audit。`
2. 目標職務審查，只在對話中呈現：
   `/linkedin-positioning-panel 請依照這份職缺描述，對 examples/sample-profile-zh.md 執行 Target Role Audit：〔貼上職缺描述〕。結果只在對話呈現，不要寫檔。`
3. 英文檔案，授權事實檢查代理並指定輸出位置：
   `/linkedin-positioning-panel Perform a General Audit of examples/sample-profile-en.md. Save the reports to ~/private/linkedin-review/. I authorize one separate factual verifier agent.`

### 在 claude.ai 對話或 Cowork 中

本組範例採附加檔案或貼上文字，不依賴本機專案路徑。請從 GitHub 上的 `examples/` 下載範例檔，附加到對話中（或貼上文字），再用文字提出需求，例如：

`請使用 LinkedIn Positioning Panel Skill，對附加的個人檔案執行 General Audit。只使用附加的檔案。`

範例檔案刻意包含團隊獎項、過去的參與，以及未說明期間的數字。審查時應保留原本的寫法，不應改成個人得獎、目前職務，也不應自行假設期間。

| 檔案 | 內容 |

| `LINKEDIN-REVISED.md` | Headline 選項、About、所有已提供的 Experience 條目、修改對照與複評 |

**報告存放位置：**

- 環境支援寫檔時，完整審查預設寫出三份報告，對話中只提供摘要與檔案路徑。
- 如果你要求只在對話呈現（例如「只在對話呈現」「不要寫檔」），就不寫檔，三份報告直接呈現在對話中。
- 如果你指定輸出位置，就使用該位置，即使位於 git 儲存庫內也一樣；Skill 不會 stage、commit 或 push 報告。
- 如果沒有指定位置，而工作目錄不在 git 儲存庫內，報告會存到該目錄下的 `linkedin-positioning-panel/<日期>-<時間>-<id>/`。
- 如果沒有指定位置，而工作目錄在 git 儲存庫內，Skill 不會把個人報告寫進該儲存庫。主機允許時，改存到儲存庫外的私人位置；不允許時，改在對話中交付，並請你指定位置。建議位置時會先提供儲存庫外的選項；如果舉出儲存庫內的例子，會註明它位於儲存庫內，由你明確選擇。
- Skill 只依實際觀察回報各位置的狀態：明確禁止寫入、嘗試寫入但失敗、只是無法列出或讀取，或尚未嘗試。無法列出目錄，不會被說成寫入失敗。遇到明確禁止時，Skill 不會設法繞過。
- Skill 不會覆寫或混入先前的報告。所選資料夾已有報告檔案時，新報告會放進新的子資料夾。
- Skill 一律不 stage、commit 或 push 報告。

不要將私人輸入資料或產出的個人報告提交到本公開專案。

本 plugin 只包含指令：一個 Skill，沒有 hooks、腳本、MCP 伺服器或其他程式碼。作者沒有營運任何後端，plugin 本身也不會傳送任何資料給作者。

| 處理環節 | 說明 |
| --- | --- |
| Claude 處理 | 你提供的個人檔案及其他內容，會作為對話的一部分傳給 Claude，依你 Claude 帳號的條款與資料設定處理。如果你授權使用代理，代理會在同一工作階段中取得授權範圍內的來源與草稿。 |
| 報告寫檔 | 環境支援寫檔時，完整審查預設會把三份 Markdown 報告寫到「輸出」一節所述的位置，報告包含你的個人檔案內容與分析。保存期限由主機決定：雲端工作階段或暫存位置中的檔案可能被清除，需要保留時，請下載或複製到持久保存的位置。只在對話呈現時不寫報告檔。執行過程中，主機也可能在工作或暫存位置建立暫存檔，例如用來檢查 PDF 版面的頁面圖片。 |

| LinkedIn 網址 | 網址只作輔助來源。Skill 不要求密碼、Cookie 或工作階段權杖，也不繞過存取限制。若開啟網址，使用的是主機提供的工具。 |

## 證據與審查原則

個人檔案中的陳述不會自動成為已獨立證實的事實。Skill 分別追蹤履歷自述、使用者確認、外部佐證、推論及未知資訊，並另外記錄查證狀態。整體品牌、獎項、類別、譯名或簡稱不同時，須先釐清關係，才能判定是否矛盾。

沒有寫明的事，不能當成任何方向的證據。過去的參與不會變成目前的成員身分；個人檔案沒有提到目前的職責，也不代表沒有這些職責。沒有來源時，Skill 不會寫出「目前不是主管」或「已不是成員」之類的說法。

事實檢查代理接收授權範圍內的來源、所有替代文案與審閱紀錄，不接收作者的自評結論。檢查重點包括時間範圍、個人與團隊歸屬、數據對象、交易類型、對目前狀態的否定推論，以及意見引用。最多修正一輪並複查一次，剩餘重大問題須明確標示。複查後才修改的文字，會標示為「Changed after recheck; not verifier-checked」，最後回覆也會先說明。另加一位檢查者不代表模擬的定位視角變成獨立審閱，也不代表來源自述獲得外部證實。

不得捏造或擅自提升職稱、雇主、日期、職責、團隊人數、營收、獎項、資格或技能。使用者的職涯期待不能被改寫成已完成的經歷。

### 候選版 3（v0.1.2 的受測候選版；SKILL.md SHA-256 `2e81d84c403da47be9335bbeff28045ecea6451fc9aefc4c8f7a2520d434ff24`）

候選版 3 只修改了寫入權限狀態的回報方式，以及在對話交付後建議輸出位置的方式，因此只測試這兩種情況。每次執行都在隔離設定中進行：只有一份同名 Skill 可用，該檔案的 SHA-256 與本候選版一致。實際載入路徑沒有直接出現在執行紀錄中，因此「載入的就是這份檔案」屬於推定。寫入的檔案、對話說明與 git 狀態都直接檢查。

| 檢查項目 | 觀察結果 |
| --- | --- |
| git 儲存庫，權限規則禁止寫入儲存庫外 | 替代交付符合預期；拒絕原因未能確認。沒有任何檔案寫入，報告在對話中交付，也沒有繞過拒絕。HEAD、索引、工作樹與遠端都沒有改變。有一個指令被拒絕，但它包含多項操作，主機沒有說明是哪一項導致拒絕；該次執行把它描述為「建立資料夾被明確禁止」，這點無法從紀錄確認。家目錄被回報為尚未嘗試，而不是被封鎖。建議的位置在儲存庫外，沒有舉出儲存庫內的例子 |
| git 儲存庫，無法列出儲存庫外的目錄，但允許寫入 | 列出目錄被拒後，Skill 嘗試寫入一次；三份有內容的報告寫在儲存庫外，也沒有宣稱任何位置被封鎖。HEAD、索引、工作樹與遠端都沒有改變 |

這兩次執行沒有涵蓋：確認由寫入操作導致的拒絕、嘗試寫入後出現錯誤的情況，以及為儲存庫內的例子加註（這兩次都沒有提出這類例子）。

### 候選版 2（較早版本；其證據不計入候選版 3）

主代理與子代理的工具呼叫都已檢查。檔案位置與 git 狀態直接以磁碟與 git 指令確認，不採信模型自述。候選版 3 沒有修改這些檢查背後的規則，但這些案例**沒有**以候選版 3 重跑。

| YAML 與名稱格式 | 已檢查 frontmatter |

| git 儲存庫，權限規則禁止寫入儲存庫外 | 沒有任何檔案寫入；報告呈現在對話中。該次執行根據被拒絕的目錄列出操作，就說家目錄被封鎖，並未實際嘗試寫入；舉出的例子位置也在儲存庫內。候選版 3 新增對應規則 |
